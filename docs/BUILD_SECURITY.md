# Защита сборки и расписания

## CI

Обязательный job `Tests, lint and Detekt` выполняет сканирование доступной
Git-истории Gitleaks до запуска Gradle. Checkout загружает историю и теги,
токен не сохраняется в Git-конфигурации. Сканер запускается с полным
маскированием секретов; его архив проверяется по закреплённой SHA-256.
Обнаружение секрета завершает проверку ошибкой. Не добавляйте исключение
ради зелёного CI: сначала определите, является ли значение действующим
секретом, и отзовите его у соответствующего провайдера.

Перед выполнением Wrapper оба Android job проверяют `gradle-wrapper.jar`
официальным Gradle Wrapper Validation. Дистрибутив Gradle 9.6.0 закреплён
через `distributionSha256Sum`; источник контрольных сумм:
https://gradle.org/release-checksums/

Actions закреплены полными SHA коммитов. Dependabot продолжает предлагать
обновления actions и Gradle; слияние остаётся ручным. Обновление Gitleaks
требует отдельно проверить версию и SHA-256 релизного архива.

## Контрольные суммы зависимостей

`gradle/verification-metadata.xml` фиксирует SHA-256 артефактов и metadata,
полученных при сборке. Обычный CI проверяет их в строгом режиме и не
перегенерирует автоматически.

При плановом обновлении зависимости:

1. Изучите источник и изменения версии.
2. В отдельной ветке выполните
   `./gradlew --write-verification-metadata sha256 testDebugUnitTest lintDebug detekt assembleDebug`.
3. Проверьте diff `gradle/verification-metadata.xml`: новые координаты,
   версии, файлы и контрольные суммы. Не добавляйте широкие trusted-artifacts
   или ignored-artifacts.
4. Повторите обычную сборку без флага генерации, затем отправьте PR.

Для AAPT2 включены Linux, Windows и macOS варианты. Обязательный Quality job
дополнительно загружает Windows/macOS артефакты из Google Maven и сверяет их
с закреплёнными SHA-256. При обновлении AAPT2 обновляйте все три платформы.

Начальная база хэшей фиксирует полученные артефакты и защищает от последующей
подмены. Само вычисление хэша не доказывает безопасность исходного пакета.
Для дополнительных задач, платформ или release-инструментов могут понадобиться
дополнительные записи после проверки; отключать verification не следует.

## Данные расписания

Загрузчик Android ограничивает размер фактически прочитанного ответа 2 MiB,
включая chunked и распакованные ответы, и умеет отменять сетевой запрос вместе
с корутиной. Некорректные данные не должны заменять последнюю рабочую копию.

Расписание публикуется отдельным Google Apps Script; локальный файл
`schedule-data/schedule.json` не является частью текущей версии.
`tools/validate-published-schedule.mjs` проверяет структуру ответа и
тестируется командой
`node --test tools/validate-published-schedule.test.mjs`.
В обязательном PR workflow выполняются детерминированные тесты;
удалённый источник проверяется при ручном `workflow_dispatch`, поскольку
доступность внешнего сервиса не должна блокировать слияние исходного кода.

Проверка структуры и корректности дат не доказывает фактическую достоверность
времени отправления. Редактор должен сверять расписание с перевозчиком.
Подробнее: [источник и публикация](guides/SCHEDULE_DATA.md).

## Настройки, требующие владельца

Состояние GitHub Secret Scanning и Push Protection не раскрывается текущим
подключением. Проверьте их в Settings. Gitleaks не заменяет запрет отправки
секретов на стороне GitHub.

Также отдельно проверьте 2FA/passkey, токены и SSH-ключи владельца, доступ
приложений, место хранения действующего Android keystore и его зашифрованной
резервной копии. Не загружайте ключ или резервные коды в репозиторий.
