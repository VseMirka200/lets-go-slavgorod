# Как работает расписание

Это руководство для редактора таблицы и сопровождающего проекта. Исходные данные редактируются в [Google Таблице](https://docs.google.com/spreadsheets/d/1UGxVGdlKwcQPmqmPQiPI8uF8LOJhdK-1vX6Lo_S291U/edit). Редактируйте расписание непосредственно в таблице.

## Как внести изменение

1. Откройте таблицу под учётной записью с правом редактирования. Сначала прочитайте лист «Инструкция».
2. На листе «Маршруты» исправьте сведения об автобусе; на листе «Рейсы» — отправления и дни работы. Каждая строка рейса должна ссылаться на существующий ID маршрута. Не меняйте заголовки столбцов и не удаляйте необходимые листы.
3. При необходимости внесите праздничные дни на лист «Календарь» и сообщения для пассажиров на лист «Изменения». Календарь необходимо поддерживать актуальным, в том числе при смене года.
4. Сверьте маршрут, направление, дни, время и цены с источником перевозчика. Сохранение таблицы происходит автоматически, но правильность сведений проверяет редактор.
5. Откройте [источник расписания](https://script.google.com/macros/s/AKfycbzus49Rc3LBZPDNcwqGteLHFViRCV9nItnX5PgvSkqSiId3mVxg1tp--7o4Cre2Mv40GA/exec): ответ должен содержать список `routes`, а не сообщение об ошибке. Затем проверьте изменённый маршрут на [сайте](https://vsemirka200.github.io/lets-go-slavgorod/schedule.html) и в приложении после обновления. Если информация не появилась, проверьте статус загрузки и доступность источника.

В строке маршрута хранятся ID, номер, название, цвет, время в пути, стоимость, способы оплаты и примечание. В строке рейса задаются маршрут, направление, время, дни работы и при необходимости ограничения по датам. Используйте предлагаемые значения в таблице и примеры на листе «Инструкция». ID маршрута должен быть уникальным и совпадать с ID в его рейсах.

## Путь данных

```text
Google Таблица → опубликованный Google Apps Script → JSON
                                      ├→ Android-приложение → локальная копия
                                      └→ сайт → копия в браузере
```

Google Apps Script опубликован как веб-приложение: его адрес, заканчивающийся на `/exec`, возвращает данные в формате JSON; для сайта используется также JSONP. Адрес источника по умолчанию указан в `app/build.gradle.kts` и в атрибуте `data-schedule-source` файла `docs/schedule.html`. В проекте нет локальной копии исходного кода опубликованного Apps Script; управление его развёртыванием выполняется в Google.

После изменения кода Apps Script обновите развёртывание веб-приложения и проверьте ответ по адресу `/exec`. Если адрес изменился, обновите обе настройки источника и адрес в проверке опубликованного расписания, затем опубликуйте сайт и новую сборку приложения. Изменение самих строк таблицы не требует новой сборки приложения. Убедитесь, что веб-приложение доступно пользователям без входа; ссылка на данные публична, поэтому не помещайте в неё секреты.

## Приложение и приоритет источников

Приложение загружает расписание из основного источника. В разделе **Настройки → Расписание → Обновление расписания** можно проверить состояние и обновить данные вручную. Для сборки адрес источника можно задать через Gradle-свойство `scheduleSourceUrl` или переменную `SCHEDULE_SOURCE_URL`.


Перед заменой локальной копии приложение проверяет структуру снимка, обязательные поля, уникальность идентификаторов и время рейсов. Если ответ пустой, повреждённый, слишком большой или недоступен, приложение использует последнюю сохранённую копию при её наличии. Локальная копия может быть устаревшей; успешная проверка структуры не подтверждает правильность данных перевозчика.

Обновление проверяется при открытом приложении, в том числе примерно раз в 30 минут; закрытое приложение не выполняет эту периодическую проверку. На экране источника отдельно показаны время загрузки копии и время последней успешной проверки. Эти отметки не являются надёжной датой фактического изменения расписания перевозчиком. При первом запуске без доступных источников расписание может отсутствовать.

## Сайт и ограничения

Сайт получает данные из Google Apps Script. После успешной загрузки он сохраняет копию в браузере и может показать её при следующей ошибке сети. При первой загрузке без сети копии ещё нет. Очистка данных браузера удаляет локальную копию. Время на странице — время загрузки в этом браузере.

Сайт выбирает ближайшую дату указанного дня недели и учитывает период действия, включённые и исключённые даты, дни работы и опубликованный производственный календарь. Календарь сохраняется вместе с копией расписания в браузере. Для праздничных дней и нестандартных изменений всё равно сверяйте отправления с перевозчиком.

## Если что-то не работает

- **Источник возвращает ошибку или пустой список:** проверьте листы, заголовки, ID, значения и доступность развёртывания Apps Script. Исправьте таблицу и снова проверьте `/exec`.
- **На сайте старые сведения:** проверьте статус загрузки, доступ в интернет и ответ источника. При ошибке сайт может показывать сохранённую копию.
- **В приложении старые сведения:** обновите расписание; локальные данные сохраняются при ошибке загрузки.

## Доверие к веб-источнику

Веб-страница использует JSONP для опубликованного Google Apps Script. Ответ JSONP выполняется как JavaScript в контексте сайта: контроль над развёрнутым скриптом фактически даёт контроль над страницей и её браузерным хранилищем. Адрес задаётся в `docs/schedule.html`, а не параметром ссылки. Доступ к редактированию таблицы, скрипта и публикации следует предоставлять только доверенным участникам и проверять перед новой публикацией.

Для удаления этой зависимости нужен источник JSON с корректным CORS или контролируемый сервер-посредник; возможность изменения Apps Script или развёртывания посредника в этом репозитории не подтверждена. До перехода CSP должна учитывать используемые Google-домены и проверяться с реальной публикацией и офлайн-режимом: разрешение JSONP-источника само по себе не ограничивает выполняемый им код.
