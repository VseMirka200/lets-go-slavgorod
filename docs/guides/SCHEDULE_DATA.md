# Как работает расписание

Это руководство для редактора таблицы и сопровождающего проекта. Исходные данные редактируются в [Google Таблице](https://docs.google.com/spreadsheets/d/1UGxVGdlKwcQPmqmPQiPI8uF8LOJhdK-1vX6Lo_S291U/edit). Не редактируйте резервный JSON на GitHub вместо таблицы: при очередной синхронизации он будет заменён.

## Как внести изменение

1. Откройте таблицу под учётной записью с правом редактирования. Сначала прочитайте лист «Инструкция».
2. На листе «Маршруты» исправьте сведения об автобусе; на листе «Рейсы» — отправления и дни работы. Каждая строка рейса должна ссылаться на существующий ID маршрута. Не меняйте заголовки столбцов и не удаляйте необходимые листы.
3. При необходимости внесите праздничные дни на лист «Календарь» и сообщения для пассажиров на лист «Изменения». Календарь необходимо поддерживать актуальным, в том числе при смене года.
4. Сверьте маршрут, направление, дни, время и цены с источником перевозчика. Сохранение таблицы происходит автоматически, но правильность сведений проверяет редактор.
5. Откройте [источник расписания](https://script.google.com/macros/s/AKfycbzus49Rc3LBZPDNcwqGteLHFViRCV9nItnX5PgvSkqSiId3mVxg1tp--7o4Cre2Mv40GA/exec): ответ должен содержать список `routes`, а не сообщение об ошибке. Затем проверьте изменённый маршрут на [сайте](https://vsemirka200.github.io/lets-go-slavgorod/schedule.html) и в приложении после обновления. Если информация не появилась, проверьте статус загрузки и доступность источника.

В строке маршрута хранятся ID, номер, название, цвет, время в пути, стоимость, способы оплаты и примечание. В строке рейса задаются маршрут, направление, время, дни работы и при необходимости ограничения по датам. Используйте предлагаемые значения в таблице и примеры на листе «Инструкция». ID маршрута должен быть уникальным и совпадать с ID в его рейсах.

## Путь данных

```text
Google Таблица → опубликованный Google Apps Script → JSON
                                      ├→ Android-приложение → локальная копия
                                      ├→ сайт → копия в браузере
                                      └→ GitHub Actions → backup/schedule.json → резерв приложения
```

Google Apps Script опубликован как веб-приложение: его адрес, заканчивающийся на `/exec`, возвращает данные в формате JSON; для сайта используется также JSONP. Адрес источника по умолчанию указан в `app/build.gradle.kts` и в атрибуте `data-schedule-source` файла `docs/schedule.html`. В проекте нет локальной копии исходного кода опубликованного Apps Script; управление его развёртыванием выполняется в Google.

После изменения кода Apps Script обновите развёртывание веб-приложения и проверьте ответ по адресу `/exec`. Если адрес изменился, обновите обе настройки источника и workflow синхронизации резерва, затем опубликуйте сайт и новую сборку приложения. Изменение самих строк таблицы не требует новой сборки приложения. Убедитесь, что веб-приложение доступно пользователям без входа; ссылка на данные публична, поэтому не помещайте в неё секреты.

## Приложение и приоритет источников

Приложение сначала загружает основной источник. Его можно изменить в настройках приложения на другой HTTPS-адрес или вернуть значение по умолчанию. Для сборки адрес можно также задать через Gradle-свойство `scheduleSourceUrl` или переменную `SCHEDULE_SOURCE_URL`.

При ошибке основного источника приложение оставляет локально сохранённое расписание. Если локальной копии ещё нет, для источника проекта оно пробует резерв GitHub. Для адреса, вручную заданного пользователем, резерв проекта не применяется. При использовании резерва показываются предупреждение и время его создания. Когда основной источник снова доступен, приложение возвращается к нему. Это исключает замену имеющейся локальной копии более старым резервом, но не доказывает, что локальная копия свежая.

Обновление проверяется при открытом приложении, в том числе примерно раз в 30 минут; закрытое приложение не выполняет эту периодическую проверку. Подпись времени в приложении связана с загрузкой или проверкой данных и не является надёжной датой фактического изменения расписания перевозчиком. При первом запуске без доступных источников расписание может отсутствовать.

## Резерв GitHub

Workflow `.github/workflows/sync-schedule-backup.yml` примерно каждые 30 минут запрашивает основной источник, проверяет полученный документ с помощью `tools/sync-schedule-backup.mjs` и при изменениях записывает `backup/schedule.json` в `main`. Его можно вызвать вручную: **Actions → Sync schedule backup → Run workflow**. Поле `backupCreatedAt` — время создания этой резервной копии, а не время последнего изменения таблицы. Расписание GitHub Actions приблизительное: запуск может задержаться или завершиться ошибкой.

Синхронизация будет выполняться только после публикации workflow в GitHub и при включённых Actions. Проверьте разрешение workflow на запись содержимого и правила защиты `main`: они могут запретить автоматический push. Ошибки проверяются в журнале запуска Actions. Не ослабляйте защиту ветки без оценки последствий; при необходимости настройте отдельное разрешение или процесс обновления через pull request. Сам JSON хранит только опубликованное расписание; ключи и токены в нём недопустимы.

Скрипт проверяет структуру и ряд обязательных полей, но не удостоверяет сведения у перевозчика. Приложение также не гарантирует обнаружение всех частично повреждённых данных. После правки обязательно проверяйте результат вручную.

## Сайт и ограничения

Сайт получает данные из Google Apps Script. После успешной загрузки он сохраняет копию в браузере и может показать её при следующей ошибке сети. При первой загрузке без сети копии ещё нет. Сайт не использует резерв GitHub; очистка данных браузера удаляет локальную копию. Время на странице — время загрузки в этом браузере.

Сайт учитывает дни недели из расписания, но его отображение не обрабатывает все исключения календаря по конкретным датам. Для праздничных дней и нестандартных изменений особенно важно сверять отправления с перевозчиком.

## Если что-то не работает

- **Источник возвращает ошибку или пустой список:** проверьте листы, заголовки, ID, значения и доступность развёртывания Apps Script. Исправьте таблицу и снова проверьте `/exec`.
- **На сайте старые сведения:** проверьте статус загрузки, доступ в интернет и ответ источника. При ошибке сайт может показывать сохранённую копию.
- **В приложении старые сведения:** проверьте выбранный адрес, обновите расписание и проверьте предупреждение об использовании резерва; локальные данные сохраняются при ошибке загрузки.
- **GitHub не обновился:** откройте последний запуск синхронизации в Actions и проверьте ошибку, разрешение на запись и защиту ветки. При отсутствии изменений новый коммит не создаётся.
