# Настройка защиты GitHub для «Поехали! Славгород»

Этот документ фиксирует необходимые проверки и правила сопровождения
Android-приложения. **Не публикуйте секреты подписи APK в репозитории.**

## Проверки перед объединением PR

GitHub Actions для этого Kotlin/Android-проекта формируют следующие
проверки (точные имена `jobs.<job_id>.name`):

| Проверка | Workflow | Что проверяет |
| --- | --- | --- |
| `Tests, lint and Detekt` | `quality.yml` | Kotlin-тесты, lint, Detekt, сборка debug APK |
| `Dependency review` | `security.yml` | Новые уязвимости зависимостей в PR |
| `CodeQL` | `security.yml` | Статический анализ **Java/Kotlin**, а не Python |
| `Validate schedule data` | `validate-schedule-data.yml` | Формат и целостность данных расписания |

На 3 ноября 2026 года в Ruleset `main` оказались устаревшие имена
обязательных проверок, перенесённые из другого проекта:
`Проверка качества в Windows`,
`Аудит зависимостей`,
`Анализ CodeQL для Python`.
Они **не соответствуют** фактическим job этого репозитория и могут
блокировать корректные PR. Настройку **нельзя исправить обычным
коммитом**: откройте
[Ruleset main](https://github.com/VseMirka200/lets-go-slavgorod/rules/26457197)
и замените три проверки на четыре перечисленных выше. Включите
`Require status checks to pass` и `Require branches to be up to date`.

Не отключайте Ruleset, PR-only изменения, защиту от удаления и force
push ради обхода заблокированного CI. Для одного владельца допустимо
иметь 0 обязательных одобрений, пока не появился второй сопровождающий.
Слияние лучше делать через squash; необходимость других merge methods
следует обсуждать отдельно.

## Защита Android-релизных тегов

Опубликованные релизы используют теги вида `3.0.2` (без префикса `v`).
Существующие Ruleset для тегов настроены на `refs/tags/v*` и
**не защищают** теги `3.0.0`, `3.0.1`, `3.0.2`.

Чтобы защитить и старые, и новые теги, измените Target tags для
обоих имеющихся Tag Ruleset на `refs/tags/*`:

- [protect-release-tags](https://github.com/VseMirka200/lets-go-slavgorod/rules/26457255):
  запрет создания новых правил здесь не нужен; сохраните запреты
  удаления, изменения и force push; **не добавляйте bypass**.
- [restrict-release-tag-creation](https://github.com/VseMirka200/lets-go-slavgorod/rules/26457294):
  оставьте только Restrict creations и исключение
  Repository admin → Always allow.

Устанавливайте шаблон `*` (в интерфейсе GitHub может отображаться как
`refs/tags/*`) именно для **Target tags**. Это защищает **все** теги,
включая технические; создавать новые теги сможет администратор.

Проверяйте после сохранения через GitHub Rulesets API, что старый
`3.0.2` теперь входит в область действия. Не создавайте пробный
релизный тег только ради проверки правил.

## Android-подпись релизов

Android использует собственное подписание APK/AAB ключом из keystore
(`.jks`/`.keystore`), **не Windows Authenticode и не SignPath**.
Приложение уже имеет release signing config, читающий
`KEYSTORE_PATH`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`,
`KEY_PASSWORD`. Ключ никогда не добавляйте в Git, переписку или
логи GitHub Actions.

Для обновлений существующего приложения нужен тот же действующий
подписывающий ключ или документированная поддерживаемая схема
ротации. Не создавайте новый keystore и не меняйте applicationId
`ru.slavgorod.transport` без отдельного плана миграции: обычное
Android-обновление может перестать устанавливаться.

Автоматического workflow публикации подписанных APK в данном
PR нет. Это отдельный этап после проверки хранения ключа,
поддерживаемого `versionCode` и способа распространения APK.

## Обслуживание

Dependabot будет продолжать открывать PR по еженедельному расписанию.
Автоматическое **слияние** Dependabot в этом PR отключено. Обновления
следует читать и сливать вручную после тестов и dependency review.

GitHub App, подключённый к ChatGPT, может изменять файлы и
создавать PR, но не может редактировать административные Ruleset.
Для изменений из двух разделов выше нужен вход администратора
в стандартный интерфейс Settings → Rules.
