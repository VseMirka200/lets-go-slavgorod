# Проверки безопасности и качества

В репозитории настроены проверки Android-кода, зависимостей и CodeQL. Условия запуска и точные команды определяются файлами в `.github/workflows/`; результат каждого запуска можно посмотреть во вкладке Actions и в pull request.

`Validate schedule data` запускает `tools/validate-published-schedule.mjs` для проверки ответа опубликованного источника; в pull request он запускается только при изменениях соответствующих файлов workflow или инструмента. Поэтому его нельзя считать проверкой каждого PR. Успешный запуск проверяет структуру и часть значений, а не достоверность расписания у перевозчика.

## Локальные проверки

Из корня репозитория запустите Android-проверки и тесты веб-кода:

```bash
./gradlew testDebugUnitTest lintDebug detekt
node --test tools/*.test.mjs
python tools/check-links.py
```

Последняя команда проверяет локальные ссылки и якоря Markdown и HTML, ресурсы CSS, а также извлекает постоянные адреса из JavaScript сайта и Kotlin-кода приложения. С ключом `--external` она дополнительно запрашивает внешние адреса. Ответы 401 и 403, перенаправления на вход и сетевые ошибки требуют ручной проверки: они не доказывают, что страница отсутствует. Проверка не обходит защиту сайтов и не выполняет пользовательские действия. Адреса, формируемые JavaScript во время работы страницы, нужно проверять отдельно в браузере.

Для ручной проверки действующего расписания передайте URL опубликованного источника команде `node tools/validate-published-schedule.mjs URL`. Скрипт также принимает путь к локальному файлу JSON. Android-инструментальные тесты запускаются командой `./gradlew connectedDebugAndroidTest` на подключённом устройстве или эмуляторе; совместимость тестовых библиотек с конкретной версией Android следует проверять отдельно.

## Настройки репозитория

Правила защиты ветки, обязательные проверки и ревью настраиваются владельцем репозитория. При выборе обязательных проверок учитывайте фильтры событий и путей: проверка, которая не запускается на каждом PR, может блокировать слияние.

По возможности включите доступные для репозитория Secret scanning и Push protection. Эти инструменты распознают не все секреты и не заменяют ручную проверку. Не добавляйте в Git токены, ключи подписи, локальные файлы и персональные данные. Особенно внимательно проверяйте изменения workflow, зависимостей, сетевого кода и источника расписания.
