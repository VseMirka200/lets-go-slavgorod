# Проверки безопасности и качества

В репозитории настроены проверки Android-кода, зависимостей и CodeQL. Условия запуска и точные команды определяются файлами в `.github/workflows/`; результат каждого запуска можно посмотреть во вкладке Actions и в pull request.

`Validate schedule data` запускает `tools/sync-schedule-backup.mjs` для проверки ответа опубликованного источника; в pull request он запускается только при изменениях соответствующих файлов workflow или инструмента. Поэтому его нельзя считать проверкой каждого PR. Успешный запуск проверяет структуру и часть значений, а не достоверность расписания у перевозчика.

Отдельный `Sync schedule backup` периодически загружает данные и при изменениях пытается обновить `backup/schedule.json`. Он требует сетевого доступа, разрешения workflow на запись и совместимости с защитой `main`. Подробности — в [руководстве по расписанию](SCHEDULE_DATA.md).

## Настройки репозитория

Правила защиты ветки, обязательные проверки, ревью и доступ бота к записи настраиваются владельцем репозитория. При выборе обязательных проверок учитывайте фильтры событий и путей: проверка, которая не запускается на каждом PR, может блокировать слияние. Ограничивайте права бота необходимым минимумом и проверяйте журнал ошибок синхронизации.

По возможности включите доступные для репозитория Secret scanning и Push protection. Эти инструменты распознают не все секреты и не заменяют ручную проверку. Не добавляйте в Git токены, ключи подписи, локальные файлы и персональные данные. Особенно внимательно проверяйте изменения workflow, зависимостей, сетевого кода и источника расписания.
